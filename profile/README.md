<p>接手一个跑了半年的账号环境，最难的部分往往不是不会配代理，而是不知道上一任改过什么。出口是独享还是共享、白名单里挂了谁的地址、浏览器配置目录备份在哪、上次换 IP 是哪天，这些信息如果只存在某个人的聊天记录里，交接期就必然出事。下面按时间线给一套可以照着走的流程，从定责开始，到切换当天的小时级顺序，再到一周观察期和回滚条件，最后给出要留存的记录清单。</p>

<h2>一、交接的起点是定责，不是交钥匙</h2>
<p>很多交接失败在第一步：新人拿到了账号密码和代理地址，却不知道这些资源对应哪些业务、出了问题该找谁。所以先画一张责任表，再谈技术动作。</p>
<h3>三类角色要分清</h3>
<p>资源所有者（谁付钱、谁签合同、谁决定扩容）、日常操作者（谁登录、谁跑任务）、技术维护者（谁管代理与网络设备）。小团队里这三者常由同一人兼任，但交接时必须显式写出，否则出问题时互相等。</p>
<h3>交接范围写成一页纸</h3>
<p>至少包含：账号清单与用途、出口地址与归属、代理端口与鉴权方式、配置文件位置、监控与告警入口、上游服务商联系人。一页纸写完，签双方名字，附日期，这份文件比任何口头交代都可靠。</p>

<h2>二、T-5 到 T-1：切换前要备齐的东西</h2>
<p>留出五个工作日，足够把材料补齐、把疑问问清，也不至于拖到业务节点上。</p>
<h3>T-5：盘资源</h3>
<p>把所有出口逐条列出，标注地区、ASN、独享或共享、到期日、月费。用 ipinfo 或 whois 核对一遍归属，确认清单与实际一致。历史遗留的、没人认领的地址，这一轮就要标记出来，交接后统一处理。</p>
<h3>T-3：导出配置与基线</h3>
<p>导出浏览器配置目录、代理配置文件、白名单规则、监控看板截图。同时记录一份基线：首字节 P95、断流次数、常用地区归属。基线是观察期的比较对象，没有基线就没法判断切换后是否变差。</p>
<h3>T-1：过一次演练</h3>
<p>由接手方独立操作一遍登录与一次典型任务，交方只看不动手。卡住的地方当场补文档，这一轮能暴露八成的信息缺口。演练结束后冻结配置，切换前不再改动。</p>

<h2>三、切换当天按小时推进</h2>
<p>切换日不要安排其他变更，也不要放在业务高峰前。建议选在工作日上午，留出足够时间处理意外。</p>
<h3>上午：先切只读，再切写入</h3>
<p>先让接手方用新环境做只读操作（查询、浏览、导出），确认出口、时区、语言三项正常；再进行写入类操作。分两步的好处是，出现异常时能立刻判断是网络问题还是权限问题。</p>
<h3>下午：换出口的动作要一次做完</h3>
<p>出口更换包括：代理地址与端口、白名单增删、DNS 策略、监控目标。四项要一起改，改一半最容易出现“能连但很慢”的中间态。每改一项记一次时间戳，方便回溯。</p>

<h2>四、T+1 到 T+7：观察期与回滚条件</h2>
<p>切换完成不等于交接完成。观察期的任务是确认稳定性，并准备好退路。</p>
<h3>每天看三个数</h3>
<p>成功率、首字节 P95、异常提示次数。与 T-3 的基线对比，波动在 10% 以内视为正常；连续两天超出，就要查原因而不是继续观察。</p>
<h3>回滚条件提前写死</h3>
<p>建议约定：出现连续两小时不可用、或核心任务失败率超过两成，立即回滚到切换前配置，回滚窗口保留七天。回滚不是失败，是预案；没有预案的切换，压力会全部压在当天操作的人身上。</p>

<h2>五、把过程留成可追溯的记录</h2>
<p>交接的价值一半在当天，一半在三个月后。有人问“这条出口什么时候换过”，能一分钟内翻到记录，才算交接合格。</p>
<h3>记录四要素</h3>
<p>时间、动作、执行人、结果。四项缺一项，记录的价值就会打折。建议直接在工单系统里建一条“环境变更”类型，字段固定，避免各写各的。</p>
<h3>敏感信息单独管</h3>
<p>账号密码、鉴权串不进普通文档，统一放密码库并开启访问审计。交接文档里只写“凭据见密码库条目 X”，既方便又安全。</p>

<h2>常见问答</h2>
<h3>交接期需要停业务吗？</h3>
<p>答：多数情况不需要。只读先切、写入后切的分步做法，可以在业务继续运行的同时完成交接。真正需要停的是出口批量更换那一段，建议安排在低峰并提前通知相关方。</p>
<h3>原负责人已经离职，信息缺失怎么办？</h3>
<p>答：从可观测的地方倒推：查代理服务商后台的订单与变更记录、查监控历史、查设备配置。补齐后按本文流程重做一次基线，不要在没有基线的情况下直接换出口。</p>
<h3>出口一定要换吗，能不能沿用？</h3>
<p>答：可以沿用，前提是地址归属清晰、租期覆盖交接期、且没有共享给其他人。若原出口与他人共用，建议借交接机会拆开，避免后续责任不清。</p>
<h3>观察期发现变差，先查什么？</h3>
<p>答：先比对路径与时区，再比对白名单与 DNS 策略。切换引入的问题八成在这四项里，逐项与 T-3 基线对照，通常半小时内能定位。</p>
